> 本文档面向**设计阶段（design 模态）**任务交接。
> 前置阶段已完成三份任务书的全部功能代码实现并通过验收，所有业务功能可正常运行。

## 一、项目背景与当前状态

### 1.1 项目概述

本项目是一套高校学生管理系统，采用前后端分离架构，包含三个端：

| 端 | 工程目录 | 默认端口 | 性质 |
| --- | --- | --- | --- |
| 学生端前台 | `student-web/` | `http://localhost:5173` | 面向在校学生，前台门户风格 |
| 后台管理端 | `admin-web/` | `http://localhost:5174` | 面向教务/辅导员/超管，工作台风格 |
| 后端 API | `server/` | `http://localhost:3000` | Express + Prisma + MySQL，前后端共用 |
| 共享前端库 | `shared-web/` | — | 类型、组件、composables、工具，两端复用 |

### 1.2 当前阶段

- ✅ **功能验收**：三份任务书（学生端 / 后台端 / 公共支撑模块）所列全部业务功能已实现并通过用户验收。
- 🎨 **当前阶段**：视觉设计升级。任务书原文写明"页面视觉设计在代码骨架完成后另行处理"，故设计工作现在启动。

### 1.3 启动与访问方式

```bash
# Windows 下双击根目录 启动.bat（或 start.bat）即可一键启动三端服务
# 启动完成后浏览器会自动打开：
#   学生端 http://localhost:5173
#   后台端 http://localhost:5174

# 测试账号
#   学生端：20240001 / 123456
#   后台端：admin / admin123
```

> 设计阶段可反复启动/访问上述地址，查看页面真实运行状态作为设计依据。

## 二、技术栈与硬约束

### 2.1 前端技术栈

| 类别 | 技术 | 版本 | 说明 |
| --- | --- | --- | --- |
| 框架 | Vue 3 | ^3.4 | Composition API + `<script setup>` |
| 语言 | TypeScript | ^5.4 | 全量类型注解 |
| 构建 | Vite | ^5.2 | |
| 状态管理 | Pinia | ^2.1 | + `pinia-plugin-persistedstate` |
| 路由 | Vue Router | ^4.3 | |
| UI 组件库 | Element Plus | ^2.7 | **设计不可更换，需基于此升级视觉** |
| 图表 | ECharts | ^5.5 | 报表统计可视化 |
| 富文本 | WangEditor 5 | ^5.1 | 仅后台通知公告使用 |
| HTTP | Axios | ^1.6 | 含 401 静默刷新拦截器 |
| 样式 | SCSS / SASS | ^1.77 | admin-web 用 sass-embedded |
| 自动导入 | unplugin-auto-import / unplugin-vue-components | | Element Plus 按需引入 |

### 2.2 设计阶段必须遵守的硬约束

1. **必须保留 Element Plus 作为底层 UI 组件库**。可定制主题、覆盖样式、组合二次封装，但不能换成 Naive UI / Ant Design Vue / Arco 等其他组件库。
2. **不得改动业务逻辑与接口调用**：`api/`、`stores/`、`composables/` 中的代码不得修改。设计阶段只动 `views/`、`layouts/`、`components/`、`styles/`、`assets/` 中的视觉与布局层。
3. **路由表保持不变**：`router/index.ts`、`router/staticRoutes.ts` 的路由路径与组件映射不可修改，否则会破坏导航/标签页/面包屑功能。
4. **共享组件 `shared-web/components/` 必须保持 API 兼容**：`PageHeader`、`StatusTag`、`EmptyState`、`FileUploader` 的 Props 名与类型不可改变，可在内部增强样式。
5. **响应式适配需求**：任务书未明确要求移动端适配，本系统主要面向 PC（≥1280px）使用，但建议做 1280/1440/1920 三档桌面响应式优化。**移动端不强求**。
6. **三端配色统一**：学生端与后台端是同一品牌下的两个产品，需共享同一套设计 Token（主色、字号、间距、圆角、阴影等），仅以导航/密度风格区分两端角色。
7. **保持现有交互约定**：
   - `StatusTag` 状态颜色映射（PENDING 黄 / APPROVED 绿 / REJECTED 红）必须保留
   - 学生状态枚举（NORMAL 在校 / SUSPENDED 休学 / RESUMED 复学 / DROPPED 退学 / HELD_BACK 留级 / GRADUATED 毕业）颜色对应关系不变
   - 报修状态流转（PENDING_REPAIR → PROCESSING → DONE）颜色对应关系不变
8. **支持深色侧边栏**：当前侧边栏为深蓝 `#001529`（Ant Design 经典深色），已是产品识别元素之一，可微调但不可整体改浅。

### 2.3 后端无关项（设计阶段无需关心）

- 数据库表结构、API 接口、JWT 鉴权、文件上传规则、WebSocket 推送、Excel/PDF 导出 —— 均已稳定，设计阶段不要触碰 `server/`。
