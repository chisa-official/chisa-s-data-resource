# 高校学生管理系统任务书 —— 公共支撑模块

> 本任务书仅覆盖**代码实现**内容，页面视觉设计在代码骨架完成后另行处理。
> 范围：底层通用能力，被学生端与后台管理端共同依赖，包括认证鉴权、文件存储、消息推送、数据导入导出、系统配置、数据库备份恢复、公共组件库与工具库。
> 本模块为后端服务工程，无独立前端工程，前端公共部分以 npm 工具包 / 复制组件形式供两个前端工程共用。

## 一、技术架构与全局约定

### 1.1 模块定位

公共支撑模块是整个系统的**底座**，所有业务模块（学生端、后台管理端）都建立在其之上。它解决跨模块的横切关注点：

- 认证与鉴权（统一身份）
- 文件存储（统一上传下载）
- 消息推送（站内信 + 短信）
- 数据导入导出（Excel 批量）
- 系统参数配置
- 数据库备份恢复
- 公共组件与工具库

### 1.2 技术栈

## 二、认证与鉴权模块

### 2.1 数据表

```prisma
model RefreshToken {
  id          String   @id @default(uuid())
  userId      String           // 学生 ID 或管理员 ID
  userType    UserType         // STUDENT / ADMIN
  token       String   @unique
  expiresAt   DateTime
  revoked     Boolean  @default(false)
  createdAt   DateTime @default(now())
}

enum UserType {
  STUDENT
  ADMIN
}
```

### 2.2 实现任务

**JWT 工具 `shared/auth/jwt.ts`**

1. `signAccessToken(payload)`：签发 Access Token，有效期 2h，payload 含 `{ userId, userType, role, roleId? }`。
2. `signRefreshToken(payload)`：签发 Refresh Token，有效期 7d，并存入 `RefreshToken` 表。
3. `verifyToken(token)`：校验签名与过期，校验是否在黑名单。

**Token 黑名单 `shared/auth/blacklist.ts`**

1. 登出时将 Access Token 加入黑名单（过期前有效），用内存 LRU 缓存（TTL = Token 剩余有效期）。
2. `isBlacklisted(token)` 供 auth 中间件调用。

**中间件 `shared/auth/middleware.ts`**

1. `authMiddleware`：从 `Authorization` 头解析 Token，校验后挂载 `req.user`。
2. `roleMiddleware(...roles)`：校验 `req.user.role` 是否在允许列表。
3. `permissionMiddleware(perm)`：校验管理员角色是否拥有接口权限标识。
4. `studentOnly` / `adminOnly`：便捷角色校验。

**密码工具 `shared/utils/crypto.ts`**

1. `hashPassword(plain)`：bcrypt 加密（saltRounds = 10）。
2. `comparePassword(plain, hash)`：校验。

**API 接口**

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/auth/refresh` | 用 refreshToken 换新 accessToken |
| POST | `/api/auth/logout` | 登出（Token 加入黑名单） |

### 2.3 验收标准

- 双 Token 机制正常，accessToken 过期后静默刷新。
- 登出后旧 Token 立即失效。
- 学生与管理员角色隔离，接口不可越权。

## 三、文件上传下载模块

### 3.1 数据表

```prisma
model FileRecord {
  id          String   @id @default(uuid())
  filename    String           // 原始文件名
  storedName  String           // 存储名（UUID + 扩展名）
  mimeType    String
  size        Int              // 字节
  path        String           // 存储相对路径
  storage     FileStorage      // LOCAL / OSS
  uploaderId  String?
  uploaderType UserType?
  bizType     String?          // 业务类型：avatar / leave_proof / notice_attach ...
  bizId       String?          // 关联业务 ID
  createdAt   DateTime @default(now())
}
```

### 3.2 实现任务

**存储抽象 `shared/file/storage.ts`**

```ts
interface StorageProvider {
  upload(file: Buffer, key: string, mimeType: string): Promise<string>; // 返回访问路径
  download(key: string): Promise<Buffer>;
  delete(key: string): Promise<void>;
  getUrl(key: string): string;
}
class LocalStorage implements StorageProvider { /* 本地磁盘 */ }
class OssStorage implements StorageProvider { /* 阿里云 OSS，按需启用 */ }
```

通过环境变量 `STORAGE_TYPE=local|oss` 切换实现，业务层无感知。

**上传封装 `shared/file/upload.ts`**

1. 用 Multer 封装 `createUploader(options)`，支持：
   - 限制文件大小（默认 10MB，可配置）
   - 限制文件类型（白名单：jpg/png/pdf/doc/xlsx 等）
   - 限制文件数量
   - 存储到 `uploads/{yyyy}/{mm}/` 目录
2. 上传成功后写入 `FileRecord` 表，返回文件访问 URL。
3. 按 `bizType` 归类存储子目录。

**下载 `shared/file/download.ts`**

1. `downloadFile(fileId)`：查询 `FileRecord`，以流式响应返回，设置 `Content-Disposition`。
2. 支持图片/PDF 在线预览（`Content-Disposition: inline`）。

**API 接口**

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/shared/files/upload` | 单文件上传 |
| POST | `/api/shared/files/upload-multiple` | 多文件上传 |
| GET | `/api/shared/files/:id` | 获取文件信息 |
| GET | `/api/shared/files/:id/download` | 下载文件 |
| DELETE | `/api/shared/files/:id` | 删除文件（仅上传者或管理员） |

**前端 `FileUploader.vue`**

1. 封装 Element Plus `el-upload`，支持单/多文件、拖拽上传、进度条、预览。
2. Props：`accept`、`maxSize`、`maxCount`、`bizType`。
3. 上传成功后 emit 文件信息（id、url、name），供表单收集。

### 3.3 验收标准

- 文件类型/大小校验生效，非法文件被拒。
- 大文件流式下载不阻塞内存。
- 本地存储与 OSS 存储可无缝切换。

## 四、消息推送模块

### 4.1 数据表

```prisma
model Message {
  id          String   @id @default(uuid())
  receiverId  String
  receiverType UserType        // STUDENT / ADMIN

  content     String
```

### 4.2 实现任务

**站内消息 `shared/message/in-app.ts`**

1. `sendMessage(payload)`：创建 `Message` 记录。
2. `sendBatchMessage(payloads)`：批量发送（如通知公告推送给全院学生）。
3. `markRead(messageId, userId)`：标记已读。
4. `getUnreadCount(userId, userType)`：未读数。

**短信 `shared/message/sms.ts`**

```ts
interface SmsProvider {
  send(phone: string, templateCode: string, params: Record<string, string>): Promise<SmsResult>;
}
class AliyunSmsProvider implements SmsProvider { /* 阿里云 SDK */ }
class MockSmsProvider implements SmsProvider { /* 开发环境打印日志 */ }
```

1. 通过环境变量 `SMS_PROVIDER=aliyun|mock` 切换。
2. 发送后记录 `SmsLog`。
3. 调用频率限制（同手机号 1 分钟 1 条），防滥用。

**WebSocket 实时推送 `shared/message/websocket.ts`**

1. 用 `socket.io` 建立连接，客户端登录后加入以 `userId` 命名的 room。
2. 新消息产生时 `io.to(userId).emit('message', payload)` 推送。
3. 前端 `composables/useMessage.ts` 监听并更新未读角标。
4. 断线自动重连。

**消息模板 `shared/message/template.ts`**

1. `renderTemplate(code, params)`：从 `MessageTemplate` 读取模板，替换 `{{占位符}}`。
2. 预置模板：审批通过、请假提醒、考勤预警、通知公告等。

**API 接口**

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/shared/messages` | 站内消息列表（分页） |
| GET | `/api/shared/messages/unread-count` | 未读数 |
| PUT | `/api/shared/messages/:id/read` | 标记已读 |
| PUT | `/api/shared/messages/read-all` | 全部已读 |

**业务集成**：各业务模块在关键节点调用 `sendMessage`，例如：
- 学籍异动审批结果 → 通知学生
- 考勤预警 → 通知辅导员
- 通知公告发布 → 批量通知目标范围学生

### 4.3 验收标准

- 站内消息实时推送（WebSocket），未读角标即时更新。
- 短信在 Mock 模式下记录日志，接入真实 SDK 后可发送。
- 消息模板占位符替换正确。

## 五、数据导入导出模块

### 5.1 实现任务

**Excel 工具 `shared/io/excel.ts`**

1. `readExcel(buffer)`：解析 Excel 为 JSON 数组（`exceljs`）。
2. `writeExcel(data, options)`：将 JSON 数组写入 Excel Buffer，支持列定义、样式、合并单元格。

**通用导入框架 `shared/io/import.ts`**

```ts
interface ImportColumn {
  field: string;          // 数据字段
  header: string;         // 表头名
  required?: boolean;     // 是否必填
  type?: 'string' | 'number' | 'date';
  validator?: (value: any, row: any) => string | null; // 返回错误信息
  transformer?: (value: any) => any; // 值转换
}

interface ImportResult<T> {
  success: T[];           // 成功数据
  errors: { row: number; field?: string; message: string }[]; // 失败行
}

async function importExcel<T>(
  file: Buffer,
  columns: ImportColumn[],
  handler: (rows: T[]) => Promise<void> // 批量入库
): Promise<ImportResult<T>>;
```

1. 解析 Excel → 逐行校验（必填、类型、自定义校验）→ 批量入库（事务）→ 返回成功/失败明细。
2. 失败行不影响成功行入库（部分成功），返回失败行号与原因。

**通用导出框架 `shared/io/export.ts`**

```ts
interface ExportColumn {
  field: string;
  header: string;
  formatter?: (value: any, row: any) => string;

async function exportExcel(rows: any[], columns: ExportColumn[], filename: string): Promise<Buffer>;
```

**模板下载**

1. `generateTemplate(columns)`：根据列定义生成导入模板 Excel（含表头、示例行、数据校验）。

## 七、数据库备份恢复模块

### 7.1 实现任务

**备份 `shared/backup/mysql-backup.ts`**

1. `backupDatabase()`：调用 `mysqldump` 命令导出 SQL 文件，存至 `backups/{yyyy-mm-dd-HHmmss}.sql.gz`（gzip 压缩）。
2. `restoreDatabase(filePath)`：调用 `mysql` 命令导入指定备份文件。
3. `listBackups()`：列出备份文件及大小、时间。
4. `deleteBackup(filePath)`：删除备份文件。

```ts
import { exec } from 'child_process';
import { promisify } from 'util';
const execAsync = promisify(exec);

async function backupDatabase(): Promise<string> {
  const filename = `backups/${dayjs().format('YYYY-MM-DD-HHmmss')}.sql.gz`;
  const cmd = `mysqldump -h${host} -u${user} -p${password} ${db} | gzip > ${filename}`;
  await execAsync(cmd);
  return filename;
}
```

**定时备份 `shared/backup/schedule.ts`**

1. 读取 `backup.schedule` 配置，用 `node-cron` 注册定时任务。
2. 默认每日凌晨 2 点备份，保留最近 30 天备份（自动清理旧文件）。

**API 接口**

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/backup/list` | 备份文件列表 |
| POST | `/api/admin/backup/run` | 立即备份 |
| POST | `/api/admin/backup/restore` | 恢复（传文件路径） |
| DELETE | `/api/admin/backup/:filename` | 删除备份 |
| GET | `/api/admin/backup/:filename/download` | 下载备份文件 |

**安全**：恢复操作需二次确认（前端弹窗 + 后端校验管理员权限），恢复前自动生成一份当前状态备份。

### 7.2 验收标准

- 手动备份生成正确的 SQL.gz 文件。
- 定时备份按计划执行，旧备份自动清理。
- 恢复操作前自动备份当前数据。

```ts
class ApiError extends Error {
```

## 九、校验与统一响应模块

### 9.1 实现任务

**统一响应 `shared/response/response.ts`**

```ts
function success<T>(data: T, message = '操作成功'): ApiResponse<T> {
  return { code: 0, message, data };
}
function fail(code: number, message: string): ApiResponse<null> {
  return { code, message, data: null };
}
function pageResult<T>(list: T[], total: number, page: number, pageSize: number): PageResult<T> {
  return { list, total, page, pageSize };
}
```

**Zod 校验 `shared/validate/zod.ts`**

1. 定义各接口的请求参数 schema（`body`、`query`、`params`）。
2. `validate(schema)` 中间件：校验失败抛 `ApiError`，校验通过后挂载到 `req`。

```ts
function validate(schema: { body?: ZodSchema; query?: ZodSchema; params?: ZodSchema }) {
  return (req, res, next) => {
    try {
      if (schema.body) req.body = schema.body.parse(req.body);
      if (schema.query) req.query = schema.query.parse(req.query);
      next();
    } catch (e) {
      next(new ApiError(400, e.errors[0]?.message || '参数错误'));
    }
  };
}
```

### 9.2 验收标准

- 所有接口响应格式一致。
- 参数校验在进入业务逻辑前完成，错误提示清晰。
